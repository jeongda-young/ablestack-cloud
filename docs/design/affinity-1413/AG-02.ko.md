# AG-02 / #1415 — Affinity 그룹 전체 선택과 조회 상태 설계

상위 Epic #1413, 누적 PR #1420, 브랜치 `dhslove/epic-1413-affinity-ui`.
기준 Europa `d9f068bbbba048313b6d38539651d19444c4d7c7`, AG-01 후속 HEAD `614cf70dd9f402c8bfbc6d8d3182742bec8bf977`.

## 재현과 목표

31번 클러스터에 전용 계정 소유 그룹 14개와 정지 VM 1개를 생성하여 현재 배포 UI에서 재현했다.

- D03: 1페이지 첫 행 선택 → 2페이지 첫 행 추가 선택 → 1페이지 복귀 시 첫 행 체크 유실.
- D04: 2페이지에서 실제로 존재하는 단일 그룹명을 검색 → 페이지 2가 API에 전달되어 데이터 없음.
- 생성 계열 공유 선택기: 조회 완료 때 초기 선택을 반복 적용하고, 사용자 선택을 로컬 상태에 반영하지 않는다. 부모도 현재 페이지 후보로 선택 ID를 재구성한다.

## 상태와 UI 계약

| 상태 | 소유자와 변경 규칙 |
| --- | --- |
| 전체 선택 ID | VM 변경은 `selectedRowKeys`, 생성 계열은 `form.affinitygroupids`. 현재 후보 페이지로 교집합을 만들지 않는다. 중복 ID는 제거한다. |
| 후보 페이지 | API의 `affinitygroup` 및 `count`. 성공만 최신 응답에 반영한다. 선택 ID에는 영향을 주지 않는다. |
| 페이지 | UI의 current/pageSize와 API page/pageSize를 제어 상태로 일치시킨다. 검색과 크기 변경은 1페이지, 검색은 크기 유지. |
| 정렬 | 변경 대화상자의 기존 현재 페이지 로컬 정렬을 유지한다. 정렬로 재조회하거나 전체 선택을 재구성하지 않는다. API 미지원 전체 결과 정렬을 약속하지 않는다. |
| 조회 실패 | 같은 범위의 이전 성공 행·개수·선택을 유지하고 오류와 재시도를 표시한다. 범위가 바뀌면 이전 후보·선택을 먼저 비운다. 정상 0건은 오류 없이 0건을 표시한다. 변경 제출은 조회 성공 후 가능하다. |
| 응답 순서 | 요청 토큰과 세션/프로젝트/소유자/Zone 범위가 모두 현재일 때만 결과·오류·로딩을 갱신한다. 이전 응답의 성공·실패가 최신 상태를 덮지 못한다. |

공유 선택 요약은 전체 개수, 페이지를 벗어난 선택과 이름을 표시한다. 아직 조회하지 못한 이름은 UUID로 표시한다. 방문한 페이지의 이름은 범위 안에서 캐시한다. 개별 항목 해제 및 모든 페이지 선택 해제를 제공한다. 표 머리글 체크박스는 현재 페이지에만 적용한다고 설명한다. 모든 해제 동작은 저장 전 로컬 선택 변경이며 되돌릴 수 있다.

변경창은 결과 0건에도 전체 건수와 현재 페이지를 별도로 표시한다. 선택 해제 버튼의 접근성 이름은 그룹 삭제와 구분하고, 안내 문구는 부모의 본문 색을 상속한다. 긴 선택 이름은 영역 안에서 생략하되 툴팁에 이름과 UUID를 유지한다.

## 생성 계열 적용

DeployVM, DeployVMFromBackup, DeployVnfAppliance, CreateAutoScaleVmGroup 네 소비자에 동일한 Affinity 전용 조회 함수를 적용한다. 다른 옵션 목록의 조회 동작은 유지한다. 부모의 선택 ID와 검토용 그룹 메타데이터도 현재 페이지 밖의 항목을 유지한다.

- 값 prop을 최초부터 반영하고 `[]` 초기화도 반영한다.
- 사전 채움은 최초 한 번 적용한다. 조회 loading 전환으로 사용자 선택을 복원하지 않는다.
- 초기 Zone 해석은 최초 사전 채움을 유지한다. 이후 Zone·소유자·세션·프로젝트 변경은 이전 선택·검색을 비우고 1페이지를 요청한다.
- 검색 이벤트는 옵션 객체의 복사본을 전달한다. 페이지 크기 변경 이벤트를 이중 구독하지 않는다.

## AG-01과의 연결

소유 범위 조회, 최신 VM 상태 확인, 선택 ID별 같은 소유 범위 사전 확인, POST 중복 방지, 비동기 job 최종 결과 확인을 유지한다. 저장은 전체 ID를 CSV로 한 번 전달하고, 명시적 전체 해제만 빈 CSV를 전달한다. 작업 결과가 불명확할 때 선택·검색·해제 잠금도 유지한다.

## 검증 및 배포 범위

실제 Ant Design Table 체크박스/페이지/요약 버튼 회귀, 네 부모의 선택/조회 통합, 기존 AG-01 및 작업 추적기 회귀를 수행한다. 31번 UI 배포 후 동일 D03/D04 절차, 페이지 크기/정렬/선택 해제, XHR 실패·역순 응답, 실제 전체 ID 저장의 job/API/DB 일치를 검증한다. 생성 마법사의 실제 선택 경로도 확인한다.

시험 VM은 시작하지 않는다. 실제 VM 배치/호스트 분산, 생성 계열 네 종류의 완전 배포는 AG-06 #1419 범위다. 생성 폼 API 타입/필터 계약은 AG-03 #1416, 전체 목록·상세·탭·대화상자의 VM 표준 정돈은 AG-05 #1418에 남긴다. UI 정적 빌드만 배포하고 JAR·DB 스키마를 변경하지 않는다. 전체 Cloud 빌드/CI는 실행하지 않는다.

검증 증거 및 최종 결과는 `docs/validation/affinity-1415/REPORT.ko.md`에 기록한다.
