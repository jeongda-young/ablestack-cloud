# AG-04: 연결 VM 현황과 그룹 중심 멤버 관리

대상 #1417, Epic #1413, 누적 PR #1420. Europa 기준 `d9f068bbbba048313b6d38539651d19444c4d7c7`에 AG-01~03을 누적한다.

## 표시와 조회

목록·상세의 연결 VM 수는 `AffinityGroupResponse.virtualmachineIds`의 고유 ID 수다. API는 그룹 조회의 페이지 처리 후 해당 그룹의 VM join 행들을 병합한다. VM 탭은 `listVirtualMachines(affinitygroupid)`의 전체 `count`와 현재 페이지를 별도로 사용한다. 검색 결과 건수는 전체 매핑 수를 대체하지 않는다. 미반환 host/project 정보는 정보 없음 또는 접근 제한으로 표시한다. 그룹 매핑 수보다 접근 가능한 VM 수가 작으면 제한 안내를 제공한다.

계정 그룹의 후보 조회에는 계정·도메인을 함께 전달한다. 프로젝트 그룹은 해당 projectid를 사용한다. 멤버 조회는 그룹 ID와 all-project 범위를 사용하여 공유 그룹의 다른 소유자 멤버를 계정 조건으로 잘라내지 않는다. 실제 변경 가능 여부는 최신 VM 소유 범위로 조회한 eligible group API에 의해 다시 확인한다. 도메인 공유 ExplicitDedication은 이 서버 측 권한 판정을 사용하며 관리자라는 이유로 타 계정의 일반 그룹 연결을 허용하지 않는다.

탭은 제목·설명, 전체/조회 건수, 도구 모음, 표, 페이지 순서다. VM 표시명·내부 이름·상태·호스트·계정·프로젝트·도메인과 제한 사유 및 VM 상세 링크를 제공한다. 같은 범위의 조회 실패는 이전 행/건수/선택을 유지하고 작업을 막는다. 세션·프로젝트·그룹 소유 범위가 바뀌면 이전 행과 선택을 비우고 늦은 응답을 무시한다. 상세 링크는 VM의 projectid를 보존한다.

## 연결 변경과 경합 계약

Stopped 일반 VM만 선택한다. External, SharedFS, Kubernetes node는 제외한다. Running VM을 자동 정지하지 않는다. 페이지·검색 밖 선택 ID와 확인 시점 VM 전체 연결 스냅샷을 별도로 보존한다.

제출은 AG-01의 세션 범위별·VM별 공유 작업 잠금을 먼저 확보한 뒤 최신 VM과 eligible group을 조회한다. 소유자/지원 상태/기존 전체 연결을 확인 시점과 비교하고 다르면 POST 없이 실패 처리한다. 변경할 대상 그룹만 Set에 추가·제거한 전체 목록을 전송한다. 다른 그룹을 교집합으로 줄이거나 현재 페이지로 대체하지 않는다.

**API 한계:** `updateVMAffinityGroup`은 전체 목록 교체이며 expected-version/CAS 매개변수가 없다. 이 UI 검사는 확인 이후~제출 전 조회에 드러난 외부 변경을 탐지하지만, 최종 조회 이후 서버 쓰기 사이의 동시 변경을 원자적으로 차단하지 않는다. 서버 원자적 delta/CAS API 및 기존 모든 호출자의 잠금 계약까지 확장하는 것은 별도 API 변경이다. AG-04에서는 JAR/DB 스키마를 변경하지 않고 이 제한을 유지·공개한다. 동시 편집이 감지되면 명시적 최신 상태 확인 후 재시도한다.

## 배치와 작업 영수증

각 VM의 preparing/submitting/job ID/최종 성공·실패/결과 불명 상태를 유지한다. 다이얼로그 닫기·탭 재방문에도 현재 앱 세션의 결과를 복구한다. 결과 불명 POST는 재전송하지 않는다. job ID가 있으면 동일 작업만 재조회한다. 부분 실패의 재시도는 실패 VM에 한정하고 최신 소유자·상태·연결을 다시 읽는다. 성공 VM은 재전송하지 않는다. 화면을 떠나 아직 제출하지 않은 VM은 미제출 상태로 남겨 명시적으로 계속할 수 있다. 앱 전체 새로고침을 넘는 영수증 영속화는 기존 AG-01과 동일하게 제공하지 않는다.

배치마다 클라이언트 문맥 ID를 부여하고 VM별 공유 잠금의 결과가 그 배치에 속할 때만 반영한다. 이 값은 API 매개변수나 인증 토큰이 아니다. 캐시가 구독을 유지하므로 화면을 떠난 뒤 완료된 작업도 원래 배치에 기록되며, 다른 화면의 후속 작업이 과거 결과를 덮어쓰지 않는다. 다른 그룹의 미완료 작업이 있으면 새 요청을 접수하지 않고 별도의 이전 작업 확인창에서 같은 job만 조회한다. 이전 작업 성공을 새 목표의 성공으로 표시하지 않는다. job ID 없는 결과 불명도 자동 재전송하지 않는다.

VM 편집창은 그룹 배치의 과거 성공/사전 검증 실패에 들어 있던 연결 목록으로 새 VM 데이터의 선택을 덮어쓰지 않는다. 재시도의 최신 VM 조회도 공유 잠금을 확보한 뒤 실행한다. 부모 상세 갱신은 부분 갱신으로 수행해 열린 결과창을 유지하며, 탭 이동은 Vue Router 이력에 기록해 VM 상세에서 Back으로 돌아올 때 가상머신 탭을 복구한다.

## 삭제

삭제 대화상자는 이름·계정/프로젝트·도메인·전체 매핑 수 및 VM/다른 그룹 보존을 안내한다. 최신 조회 실패 시 삭제를 막고, 확인 이후 매핑 구성이 달라졌으면 영향 정보를 갱신하고 재확인을 요구한다. 목록의 선택 삭제와 우클릭 작업도 보존하되 선택 대상을 동결한 뒤 같은 영향 확인을 그룹마다 차례로 요구한다. 한 그룹의 최종 job 성공 이후에만 다음 대상으로 진행하며, 실패/결과 불명은 해당 대상에서 멈추고 성공 대상을 다시 제출하지 않는다. 중간 취소는 미제출 대상을 삭제하지 않는다. 단일 상세 삭제가 끝나면 목록으로 돌아간다.

## 검증

단위/컴포넌트 검증은 전체 건수와 페이지 분리, 전체 연결 보존, 소유권/상태/공유 범위, 외부 변경, 부분 실패 재시도, unknown 중복 방지, 세션 범위 초기화, 삭제 재확인을 포함한다. 31번에는 전용 Stopped VM·계정·프로젝트·L2·그룹을 만들고 실제 UI/API/DB를 대조한다. 운영 VM과 기존 그룹은 변경하지 않는다. 정적 UI만 WEB-INF·설정·JAR·PID를 보존해 배포한다. 전체 Cloud 빌드는 실행하지 않는다.

후속 AG-05는 전체 목록·상세·탭·대화상자 스타일 정돈, AG-06은 실제 호스트 배치와 통합 행렬을 담당한다.
