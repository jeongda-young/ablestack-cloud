# AG-06: API·UI 통합 및 실제 호스트 배치 검증

대상 #1419, Epic #1413, 누적 PR #1420. 최신 Europa `8c5a92a4d9978229221613f4ff3e36e2df54daeb`를 병합한 `a57b608f719`에서 검증한다. 선행 AG-01~05의 UI와 API 계약을 유지하고 이번 검증에서 확인한 결함만 수정한다.

## 격리와 증거

31번 관리 서버와 KVM 3대의 가용 CPU·메모리·공유 스토리지를 새로 조사한다. `qa-ag06-` 접두사의 전용 그룹·VM·계정·도메인·프로젝트·역할만 변경하고 기존 119개 VM과 4개 그룹은 Affinity 투영을 보존한다. 운영 VM 정지, 호스트 비활성화, 스토리지 고갈은 하지 않는다. 사용자가 승인한 시험 자원만 시작·정지·삭제한다.

UI 변경 요청, 최종 비동기 결과, API/DB의 그룹 매핑과 VM host ID, 3개 호스트의 실제 실행 도메인을 대응한다. 비밀번호·키·세션은 증거에서 제거한다. 시험 오류는 원래 결과로 남기며 수정 후 재검증을 별도 기록한다.

## 행렬

1. AG-D01~D07의 선행 재현/집중 회귀 근거와 이번 UI 경로를 연결한다. 생성·오류 수정·검색·상세·이벤트·0/1/다중 페이지·선택·연결/해제·다른 그룹 보존·영수증·삭제 영향 재확인을 검증한다.
2. 관리자·일반 사용자·프로젝트·도메인 관리자·제한 역할과 도메인 공유/Zone 지원 조건을 실제 API 및 UI로 확인한다. Running VM 변경은 사용자가 의도하지 않은 자동 정지 없이 차단되어야 한다.
3. VM 생성 마법사의 Affinity 선택과 실제 생성/시작을 확인한다. 엄격 affinity는 동일 호스트, 엄격 anti-affinity는 서로 다른 호스트, 선호 2종은 정상 배치와 강제 호스트 제약 충돌에서 관찰한 동작을 기록한다. 공유 호스트의 용량 고갈은 미검증으로 명시한다.
4. 공통 VM UI·VM 생성/백업/VNF/Kubernetes/AutoScale 소비자는 기능 변경 범위를 구별해 집중 테스트와 실제 UI 조회/선택으로 회귀 확인한다. 별도 인프라 생성이 필요한 전체 제품 시나리오를 Affinity 합격으로 확대하지 않는다.
5. AG-05의 VM 표준 5개 영역과 42개 테마/화면 상태 증거를 유지하고 최종 UI에서 주요 경로·키보드·좁은/짧은 화면을 다시 확인한다. 캡처 렌더링 제한과 실제 DOM/동작 검증을 구별한다.

## 배포와 종료

실제 마법사에서 선택기의 영문 정책 원문만 남는 불일치를 확인해 공통 정책 표시 컴포넌트와 표 내부 가로 스크롤을 적용한다. API 원문과 선택 ID는 바꾸지 않는다.

최종 모바일 실측에서 공통 `.ant-table-body`의 최소 너비 500px가 256px 선택기 밖으로 넘치는 문제를 확인했다. Affinity 선택기에 한정해 해당 최소 너비를 해제하고 본문 너비를 부모에 제한한다. 페이지 도구는 줄바꿈하며 실제 가로 스크롤은 표 본문 안에 남긴다. 원래 넘침 실측과 수정 후 측정을 구별해 보존한다. 첫 수정의 배포 후에도 공통 모바일 규칙의 높은 specificity 때문에 최소 너비가 유지되는 것을 확인했다. 선택기 내부의 `min-width` 선언에만 `!important`를 적용해 해당 규칙을 덮어쓰고 재검증한다. 첫 수정 실패도 별도 증거로 보존한다.

도메인 관리자가 타 계정 그룹을 조회할 때 `projectid=-1`을 강제하면 빈 결과가 반환되지만 계정/도메인으로 조회하면 정상 응답하는 것을 재현했다. 멤버·삭제 영향의 최신 그룹 조회와 일반 그룹 멤버 조회는 그룹의 실제 계정/프로젝트 소유 범위를 사용한다. ExplicitDedication 공유 그룹은 도메인의 여러 소유자를 포함할 수 있으므로 재귀·전체 프로젝트 범위를 유지한다. 서버가 도메인 관리자의 타 계정 그룹 쓰기를 거절하는 권한 계약은 변경하지 않는다.

UI는 WSL ext4에서 빌드하고 활성 `/usr/share/cloudstack-management/webapp`에 정적 파일만 배포한다. WEB-INF/META-INF·설정·JAR·PID와 FTCTL 마커를 보존하고 파일 해시·Mold active·HTTP 200을 확인한다. 이번 범위의 백엔드 변경이 없으면 JAR을 교체하지 않는다. 전체 Cloud 빌드는 별도 요청 전 실행하지 않는다.

시험 자원은 추적 목록에 기록해 정리하고 활성 VM·볼륨·NIC·그룹·매핑·계정·사용자·프로젝트·도메인·역할이 0인지 확인한다. 삭제 이력은 활성 잔여와 구분한다. 마지막 조회와 전체 연결 교체 사이의 CAS 없는 경합, 앱 재로드를 넘지 못하는 영수증, 안전하게 재현하지 못한 용량 조건을 보고한다. PR은 누적 Epic PR을 갱신하며 병합은 별도 요청 대상이다.
