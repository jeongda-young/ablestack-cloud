# AG-07: 공유 그룹 count·페이지 정합성과 멤버 탭 표준 수정

대상 #1421, Epic #1413, 누적 Draft PR #1420. 기준 Europa `8c5a92a4d9978229221613f4ff3e36e2df54daeb`, 기존 Epic 브랜치를 이어 사용한다.

## 문제와 계약

기존 서버는 계정/도메인 검색과 공유 그룹 검색에 각각 offset/limit을 적용한 뒤 상세 행을 합치고 count를 더한다. 같은 공유 그룹이 두 범위에 들어가면 응답에서는 합쳐져도 count가 중복되고, 공유 그룹이 계정 페이지와 별도로 잘려 페이지 구성이 일관되지 않는다. AG-06에서 고유 그룹 4개에 count=5, 크기 2의 빈 세 번째 페이지를 재현했다.

`buildACLSearchParameters`가 정한 계정·도메인·프로젝트 범위와 기존 상속 공유 규칙을 유지한다. 일반 범위와 적법한 공유 그룹 ID 범위를 OR로 묶고, ID/이름/유형/키워드는 그 바깥에서 AND로 적용한다. 동일한 DISTINCT 그룹 ID 쿼리에 count·ID 정렬·offset/limit을 한 번만 적용한다. 페이지에 속한 그룹의 상세 VM 행은 이후 모두 조회하며 그룹 ID 순서를 유지한다. 한 그룹의 VM 여러 개를 별도 그룹으로 세거나 페이지에서 자르지 않는다.

공유 후보 ID만 수집하고 일반 그룹 전체를 메모리에 적재하지 않는다. 같은 도메인의 여러 허용 계정은 공유 범위를 한 번만 수집한다. 부모의 `subdomain_access=false` 공유는 자식에게 추가하지 않는다. 프로젝트 포함/제외, 비재귀 조회, VM 지정 조회와 접근 거절은 기존 계약을 유지한다. 권한 확대·쓰기 허용·DB 스키마 변경은 포함하지 않는다.

## 가상머신 탭 UI 표준 정정

사용자가 지정한 표준은 **제목·설명 없이 바로 작업 버튼으로 시작**하는 배치다. AG-05/06의 상단 제목·설명 배치는 이 기준에 맞지 않았으므로 제거한다. 전체 매핑 수와 조회 결과 수의 차이는 표 아래 페이지 영역에서 안내한다. 후속 표준 정정에 따라 상단은 연결/해제/결과 버튼 뒤에 **아이콘+업데이트 버튼을 액션 영역의 마지막에** 두고, 우측에는 검색만 배치한다. 연결 변경 대화상자 안의 동작 설명과 Running 제한·권한·오류 안내는 해당 동작에 필요한 정보로 유지한다.

## 검증과 배포

- 실제 SearchBuilder/Criteria를 사용해 중복 count·전역 페이지, 필터의 OR 우회 방지, 프로젝트 포함/제외, 공유 상속·중복 도메인, 빈 페이지, VM 접근 거절을 집중 테스트한다.
- WSL ext4에서 변경 Maven 모듈 `server`와 필요한 UI만 빌드한다. 전체 Cloud 빌드는 실행하지 않는다. 기존 로컬 의존성이 최신 소스와 맞는지도 확인한다.
- 31번의 실행 JAR 형식과 클래스 위치를 확인한다. 원본을 백업하고 변경 클래스만 반영할 경우 원래 JAR의 나머지 엔트리 해시·클래스 호환성·실행 경로를 비교한다. 관련 없는 JAR/호스트 패키지·DB 스키마를 교체하지 않는다.
- UI는 활성 webapp의 정적 파일만 배포하고 WEB-INF/META-INF·설정 및 관련 없는 런타임을 보존한다. JAR 교체에 필요한 관리 서비스 재시작 후 Mold active, HTTP 200, 로그인/API와 실제 서버 로그를 확인한다.
- 새 `qa-ag07-` 전용 계정·도메인·프로젝트·역할·공유/일반 그룹·Stopped VM을 추적한다. 수정 전 동일 결함과 수정 후 역할/필터/0·1·다중 페이지·다중 VM 매핑을 UI/API/DB로 검증한다. 공유 시험을 위해 운영 인프라를 전용화하지 않는다.
- 라이트/다크와 1440×900·390×844/480에서 버튼이 첫 콘텐츠인지, 검색·페이지·연결/해제·삭제·Running 제한·대화상자 설명이 유지되는지 확인한다. 새 자원 활성 잔여 0과 기존 4개 그룹/119개 VM Affinity 투영 보존 후 이슈를 완료한다.
