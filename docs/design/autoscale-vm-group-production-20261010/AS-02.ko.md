# AS-02 / #1348 다단계 생성·복구·보상 설계

AS-01 이후의 기존 Mold 생성 마법사에 적용한다. 다음 #1350의 런타임 스케일 동시성, #1349의 정책 계산, #1355의 메뉴 전체 UI 통합은 착수하지 않는다.

## 서버 요청 및 기존 async job

- 프로필·조건·정책·그룹 생성 API의 기존 선택적 UUID `customjobid`를 재사용한다. 조회 API의 `requestid`와 동일한 값이다. 기존 클라이언트의 미지정 동작은 유지한다.
- 서버 요청 저널은 요청 id, 명령, 시작 사용자/소유 계정, 정규화한 API 파라미터의 SHA256, 상태, 생성 자원 식별자 및 부모 작업 UUID/단계 키만 저장한다. UserData·SNMP 값·API 키 등 원문은 추가 저장하지 않는다.
- 같은 요청의 자원 생성과 job 접수를 분산 잠금으로 직렬화하고, 동일 사용자/소유자/명령/명세일 때만 기존 자원과 같은 async job을 반환한다. 변경된 명세·다른 사용자·삭제된 자원은 거부하며 다른 자원을 만들지 않는다.
- 자원과 저널의 연결은 같은 DB 트랜잭션으로 커밋한다. 생성/조회 API와 이벤트에 요청 id 및 자원 id를 연결한다. 조회는 시작 사용자에게만 허용한다.
- 전체 생성 명세와 게스트 설정을 새 서버 작업에 장기 저장하는 방식 대신, 기존 Cloud async job의 실행 책임을 유지하고 단계별 서버 영수증으로 응답 유실을 재조정한다. 그룹 설정 재진입은 이미 완료된 그룹을 다시 설정하거나 실패로 삭제하지 않게 한다.
- 요청 조회 응답은 기존 Cloud API와 동일하게 `autoscalecreationrequestresponse.autoscalecreationrequest` 객체로 반환한다. 완료된 async job의 `removed`는 Cloud의 완료 표시이므로 결과/재요청 조회에 재사용하며, 실제 job 정리 이후에는 커밋된 자원 상태로 조정한다.
- Europa 명시적 스키마 마이그레이션에 독립 요청 저널을 추가한다. 기존 AutoScale 테이블의 계약은 유지한다.

## UI 작업 수명과 복구

- 제출 전부터 중복 클릭을 잠그고 모든 단계는 success/failed/unknown으로 반드시 종료한다. 공통 job tracker를 통해 중복 폴링 없이 연속 조회, 제한된 재시도, 기한, 중단을 적용한다.
- 브라우저에는 사용자/서버/프로젝트별 작업 id, 단계 요청 id·job/resource id, 비밀이 아닌 정책/그룹 계획만 보존한다. 프로필 UserData·변수 값·SNMP 값·자격 증명은 브라우저에 저장하지 않는다.
- 응답 유실·조회 실패·새로고침은 서버 영수증과 기존 job을 GET으로 재조회한다. 결과 불명확 상태에서 생성 POST를 자동 반복하거나 자원을 정리하지 않는다. 사용자가 명시적으로 복구를 선택한 경우에만 동일 customjobid/명세로 접수 공백을 복구한다. 서버 영수증이 NOTFOUND이며 자원/job 식별자가 없는 요청도 이 명시적 복구에 포함하며, 늦은 서버 접수는 같은 UUID로 중복 방지한다. 미접수 프로필은 비밀을 저장하지 않으므로 폼을 다시 확인하고, 접수된 프로필은 영수증 조회를 먼저 수행한다.
- 새로고침으로 남은 진행 중 기록은 재조회 가능한 결과 확인 상태로 복원한다. 이전 화면의 늦은 POST/조회 응답은 복구한 화면의 기록을 덮어쓰지 않는다.
- 메뉴 이탈/로그아웃/프로젝트 전환 때 조회 타이머와 뷰 구독을 정리한다. 서버 job은 취소됐다고 표시하지 않는다. 동일 사용자/문맥으로 돌아오면 복구 안내·조회 계속·안전한 정리를 제공한다.
- 현재 Mold Modal/Steps/Alert/Button을 사용한다. 작업 id, 실패 단계, 생성/보존/정리 실패 자원과 한국어 후속 동작을 표시하고 양 테마의 가독성을 확인한다.

## 보상 경계

- 이번 작업의 요청 영수증으로 소유가 확인된 자원만 정책→조건→프로필 역순으로 보상한다. 성공/진행 중/결과 불명 그룹은 자동 삭제하지 않는다.
- 공유 정책·조건·기존 LB·템플릿·망은 삭제 대상에 넣지 않는다. 기존 서버의 in-use/권한 검증을 재사용하고 공유된 자원이면 남겨 UI에 식별자·실패 사유·재시도를 제공한다.
- 삭제 실패 또는 응답 유실은 목록/상태 재조회 후 잔여 자원으로 표시하며 정리 성공으로 가정하지 않는다. 그룹 NEW 생성 실패의 서버 정리도 매핑·스케줄·모니터 기록을 함께 처리한다.

## 검증 계획

ASY-01~04의 프로필/조건/양 정책/그룹 단계 실패, ASY-05의 동기 응답 및 job 0→1/2, ASY-06 조회 실패/기한/세션, ASY-07 중복 클릭·메뉴 이탈, ASY-08 응답 유실·새로고침, ASY-09 정리 실패/복구, ASY-10 공유 자원 보호를 집중 계약 테스트와 31/32 실제 UI 장애 주입으로 대조한다. 결과별 API/DB 개수·요청/자원 연결·LB/VM 상태를 확인한다.

빌드는 WSL ext4의 변경 Maven 모듈 및 UI만 수행한다. 31 신규 VM/라우터는 GFS2 SPARSE 이상(THIN 금지), 32는 실제 krbd를 확인한다. 최종 UI 정상 생성·한글·다크/밝은 모드까지 완료 후 기존 #1348 및 누적 Draft PR #1356을 갱신한다. 장시간 운영 확인은 #1354에 유지한다.
