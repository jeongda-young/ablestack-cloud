# AS-06 (#1352) 정책·프로필·예약 변경 계약

## 범위와 완료 조건

Epic #1346 / 누적 Draft PR #1356 안에서 정책·프로필·예약 편집을 현재 Mold 구성요소로 보완한다. GT/GE/LT/LE/EQ는 #1349 구현을 재사용하고 0 임계값과 왕복 보존을 검증한다. 모듈/API·schema·server 및 UI만 빌드한다. 31 GFS2는 Sparse 이상, 32 krbd를 대상으로 프로젝트/일반 사용자, 한글, 밝은/어두운 테마에서 실제 UI 경로를 검증한다. 장시간 운영 시험 OPS-10은 최종 #1354로 유지한다. 다음 작업은 #1353이며 자동으로 착수하지 않는다.

## 확인된 변경 대상

- 서비스 오퍼링 단독 변경도 연결 그룹 전체 Disabled 및 진행 중 작업 없음 조건을 적용한다. 생성/편집의 활성 고정 오퍼링, 사용 가능한 Ready 템플릿, 소유자 권한, 배포 매개변수 검증을 일치시킨다.
- 누락한 필드는 유지한다. 매개변수 전체 제거는 명시적인 clear 플래그로 처리하며 비동기 완료까지 로딩을 유지하고 성공 뒤 화면을 다시 읽는다. 프로필 변경은 이후 생성 VM에만 적용하며 기존 VM을 변경하지 않는다.
- 정책/조건 변경은 공유하는 그룹을 안내한다. 프로젝트 소유권을 생성 요청에 포함하고 마지막 정책/조건 제거를 막는다. 새 조건/정책 연결 실패는 확정된 실패만 보상하고 결과 불명은 재전송하지 않는다.
- 예약은 알 수 없는 시간대를 GMT로 바꾸지 않는다. 입력 날짜는 선택 시간대의 벽시각이며 DST로 존재하지 않거나 두 번 발생하는 시각은 명시적으로 거절한다. 편집 날짜도 예약 시간대로 왕복한다.
- 분 반올림을 버림으로 수정하고 예약 시작 경계는 포함한다. 실행 잠금 획득 실패/이미 제출된 작업은 실행하지 않는다. 최신 예약의 활성/자원/동작/기간을 다시 확인한다. 제출 이벤트를 완료로 기록하지 않는다.
- 예약은 수동 변경과 동일한 updateAutoScaleVmGroup 및 그룹 잠금/최소·최대 검증을 사용한다. Disabled 그룹에는 범위만 저장하고 VM을 시작하지 않는다. 동일 그룹·동일 시각은 가장 먼저 생성된 예약(ID가 작은 예약) 하나만 실행하며 나머지는 로그에 충돌로 기록한다. 진행 중 작업과 충돌한 변경은 거절하고 자동 재전송하지 않는다.

## 검증 계획

1. Java: 활성 그룹의 오퍼링 단독 편집 거절, Ready/활성/매개변수 소유권·형식, 명시적 제거/누락 유지, UserData 유지, 공유 변경 제한 및 최소 1조건/정책.
2. Java: 시간대/DST/기간, 시작 경계, 분 경계, 실행 잠금/중복/삭제·Disabled 예약, 예약과 수동 변경의 동일 명령. 기존 VM 예약 회귀도 포함한다.
3. UI: 프로젝트(31)·일반 사용자(32)에서 5연산자/0/단위, 조건/정책 추가·수정·해제, 공유 영향 안내, 매개변수 마지막 제거, 프로필/사용자 데이터 변경 및 새 VM에만 반영.
4. UI: 예약 추가·편집·활성/비활성, UTC/KST 왕복, 잘못된 범위/DST, 실제 분 경계 실행, Disabled 그룹 범위 변경, 동일 시각 충돌. API/DB/호스트는 UI 실행의 보조 증거로만 사용한다.
5. 빌드/RAT/체크스타일/UI 린트와 실제 활성 JAR·정적 파일 SHA256, WEB-INF 보존, HTTP 200, 실제 검증 VM이 위치한 호스트의 스토리지 경로를 기록한다. 전체 CI/장기 무손실 시험과 구분한다.

## 결과

정책·프로필·예약 계약 구현, 254건 Java/162건 UI 집중 테스트와 변경 모듈/UI 빌드, 31/32 배포 및 핵심 UI 검증을 완료했다. 승인된 전용 VM4대·ROOT/DATA8개(520GiB)의 UI 축소·정리 및 기존 VM·그룹 보존을 완료했다. #1352 완료, Epic 진행6/9이며 다음 #1353은 사용자 지시까지 대기한다. [검증·배포·보존 상태와 제한](AS-06-validation.ko.md)을 참조한다.
