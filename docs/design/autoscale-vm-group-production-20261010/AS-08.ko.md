# AS-08 최종 통합·24시간 운영 확인 설계 (#1354)

Epic #1346의 마지막 운영 확인 이슈다. #1347~#1353, #1355는 Closed다. 2026-10-13 사용자 지시로 PR #1356을 병합해 구현 기준을 확정하고 Epic #1346을 닫되, #1354는 Open으로 유지한다. 장기 관찰은 모든 구현·기능 검증과 최종 대표 UI 통합 게이트 통과 뒤에만 수행한다.

## 환경과 최종 게이트

31 GFS2 Sparse/KVM/VirtualRouter/프로젝트와 32 Ceph krbd/KVM/VirtualRouter/일반 사용자, 32 VpcVirtualRouter를 확인한다. 동일 오토스케일 구현·UI를 사용하고 스토리지·서버별 설치 설정은 유지한다. GFS2 Thin은 사용하지 않는다.

- 변경된 31 관리 JAR 및 UI 진입 파일/locale을 검증된 배포 기준으로 복원하고 WEB-INF/config와 변경 전 백업을 보존한다.
- 실제 UI에서 최소 인원 유지로 1→3 확장, min1/max3 복원 뒤 CPU 저부하 정책으로 3→2→1 축소를 확인한다. Running·활성 LB 매핑·HTTP 응답 및 실제 GFS2 qcow2/krbd raw를 각각 대조한다.
- 기존 원본7VM/ROOT·AS01/AS02 그룹·프로필/CPU정책·Disabled 예약을 보존한다. 이번 추가VM4/ROOT4만 자동 축소에서 정리됐음을 DB/API와 전체6호스트에서 확인한다.
- 한글·라이트/다크·프로젝트/사용자·운영 상태/VM 프로필/LB 및 업데이트 대화상자를 실제 UI로 다시 확인한다. 전체 UI 변경 검증은 AS-09의 321 tests·168 관측·48개 UserData 화면 크기 검증에 연결한다.
- 생성/보상/결측/쿨다운/경쟁/관리 재시작/드레인/실패 보상/예약 등의 선행 실검증과 집중 경계 테스트를 구분하여 참조한다. 60개 사례를 이번에 전부 재실행한 것으로 기록하지 않는다.

## 마지막 운영 관찰

기간: **2026-10-13 11:44:15~2026-10-14 11:44:15 KST**, 최소24시간. AS04 두 그룹은 Enabled/min1/max3, 32 VPC는 Enabled/min1/max1. AS01/AS02는 기존 Disabled이며 그룹/원본 VM을 보존한다. 시작 후에는 기능 시험·장애 주입·배포·재시작·프로필/정책/예약 변경을 하지 않는다.

| 주기 | 수집/확인 |
|---|---|
| 5초 | 세 애플리케이션 LB HTTP200·본문 hash·latency·실패와 수집 공백 |
| 1분 | Cloud 그룹/VM/LB·min/max·작업·최근 평가/수집 시각·그룹 ERROR 이벤트 |
| 5분 | 로컬 DB 활성 멤버/LB·고아 자원·통계 행/최고/최저 시각/retention 설정, 관리 PID/RSS/스레드/fd·Cloud JVM heap·배포/설정 fingerprint |
| 30분 예약 | 위 수집 기록과 실제 Mold UI를 확인. 변화 없으면 채팅 알림 없이 기록만 갱신 |
| 1/6/12/24시간 | 기존 #1354에 중복 없는 진행 기록. 이상·완료·사용자 조치 필요 시 알림 |

서버의 별도 읽기 전용 수집기는 PC와 독립적으로 실행하고 기간이 끝나면 자동 종료한다. Codex의 채팅 예약 확인에는 PC와 앱 실행이 필요하다. 인증 정보는 일회성 stdin으로 받아 메모리에만 보관하며 출력·저장·Git에 포함하지 않는다. 표본은 서버700권한의 전용 디렉터리에 저장한다. 수집 도구는 [tools/as08_observer.py](tools/as08_observer.py), 프로세스 시작 도구는 [tools/as08_launcher.py](tools/as08_launcher.py)다.

## 합격/실패와 마무리

24시간 실제 연속 기록·정상 조회·세 HTTP 대상 응답·인원 범위·VM/LB 일치·원본 보존·반복 오류/고아 자원 없음·통계 정리 및 JVM/RSS/스레드/fd 추이를 함께 검토한다. HTTP10초/API100초 이상 수집 간격, API/DB/HTTP 오류, collector 중단, 배포/PID/설정 변경은 기록을 보존해 원인을 확인한다. 수집 공백이나 warm-up/GC의 RSS 상승을 근거 없이 PASS/누수로 확정하지 않는다. JVM heap은 jstat 설치가 없어 Cloud 관리 지표의 값과 collectiontime으로 확인한다.

종료 후에만 이번 Enabled 세 그룹을 UI에서 Disabled로 복원하고 기존 VM/ROOT와 예약을 보존한다. 전용 수집기 PID/cmdline 확인 후 정리한다. 최종 UI·자원·서비스·해시와 운영 기록을 문서 및 이미 병합한 PR/기존 이슈에 반영한 뒤 #1354 완료 여부를 판정한다. Epic을 다시 열거나 PR을 다시 병합하지 않는다. 새 이슈·새 채팅·다음 별도 작업을 자동 수행하지 않는다.
