# AS-09 보완: 작업 범위·대화상자·선택 칼럼·운영 가독성

이슈 #1355, Epic #1346, 누적 PR #1356. 사용자 보완 요청으로 재개하며 이전 상단 선택행 액션 목업은 이 설계로 대체합니다.

## 작업 배치

기존 VM 탭처럼 전체 작업은 상단 툴바(왼쪽 정렬, 주 버튼 파란 아이콘+텍스트, 나머지 일반 버튼, 업데이트 마지막), 개별 자원 작업은 해당 표 행의 작업 칼럼에서 실행합니다. 새 액션을 만들지 않습니다. 행 작업이2개 이상이면 VM NIC/설정 탭처럼 down 버튼 드롭다운으로 모으고, 한 개이면 직접 버튼으로 표시합니다. 삭제 메뉴는 대상 이름/ID가 있는 Mold 확인 대화상자로 이어집니다.

| 탭 | 상단 전체 작업 | 행 작업 |
|---|---|---|
| 운영 상태 | 업데이트 | 없음 |
| VM 프로필 | 프로필 편집·사용자 데이터 변경·매개변수 추가·업데이트 | 매개변수 삭제 |
| 부하 분산 규칙 | 단일 규칙 편집·태그·세션 고정·보호된 삭제·업데이트 | VM/IP 연결 해제 |
| 스케일업/다운 | 정책 추가·업데이트 | 정책 편집·조건 추가·정책 연결 삭제, 조건 편집·조건 연결 삭제 |
| 스케줄 | 스케줄 추가·업데이트 | 스케줄 편집·삭제 |

정책 선택은 정책 이름으로 하며 선택한 정책의 조건 표를 아래에 표시합니다. 행 액션은 클릭한 자원 ID를 직접 전달합니다. 확인을 열 때 그룹·프로필·정책·예약·VM/IP tuple을 고정하고 실행 시 현재 목록과 다시 비교합니다. 조회 갱신/그룹 이동으로 다른 대상을 실행하지 않습니다. 상태·권한·공유 영향·마지막 정책/조건·진행 중 작업 보호 및 비동기 처리 계약은 유지합니다.

## 사용자 데이터 잘림

공용 ResetUserData의 기존 폼 90vw/45vw와 검색 25vw가 760px Mold 모달보다 커지는 것이 원인입니다. AutoScale API 경로에만 컨테이너 기준 100% 폭·min-width 0·검색 최대320px/100%·긴 이름 줄바꿈·고정 table layout을 적용합니다. 기존 VM 경로는 기존 클래스/크기로 유지합니다. 외부 modal만 화면에 들어오는지 보지 않고, 폼·검색·표·분할 탭·취소/확인 버튼과 실제 가로 넘침을 검증합니다. 좁은 화면은 본문 스크롤을 사용하고 버튼을 접근 가능하게 유지합니다.

## 목록 선택 칼럼

기본6칼럼(이름·상태·멤버/범위·네트워크/LB·최근 확인·소유자)과 프로젝트 모드의 기존 프로젝트 칼럼을 유지합니다. VM 공통 ListView 칼럼 메뉴와 사용자/경로별 기존 저장 방식을 재사용합니다. 사용자 확정 옵션6항목: 도메인·네트워크 이름(독립 칼럼)·LB 제공자·폴링 주기·생성 일시·Zone 이름. ID5개와 공인 IP/개별 포트는 선택 옵션에서 제외합니다. 기본 통합 네트워크/LB 칼럼은 유지합니다. Zone 옵션을 켤 때만 그룹의 연결 네트워크를 listNetworks로 정확 ID 및 소유 범위 내에서 조회하고 네트워크별 중복 요청을 제거합니다. 실패/권한 없음/미기록을 표시하며 Zone을 추정하지 않습니다. 조회 도중 그룹/사용자/프로젝트/목록 세대가 바뀌면 늦은 응답을 무시합니다. 별도 권한 확대나 API/DB 변경은 하지 않습니다. 선택/해제 후 화면 이동·새로고침에도 유지합니다. 기존 범위 칼럼 설정은 통합 칼럼으로 이관하되 새 인프라 선택을 소실하지 않습니다.

## 운영 상태 가독성

그룹 상태·대상 멤버/범위·폴링 주기는 상단 강조 박스로, 실행/전환/정지/오류/정리 등 집계는 작은 데이터 박스로 표시합니다. 수집/확인/스케일/드레인 시각은 테두리 있는 설명 표로 묶습니다. 최근 평가는 별도 카드 안에서 시각 정보와 정책별 카운터·관측값·기준·표본·자원·결과 표로 표시합니다. 멤버 표를 유지하고 최근 이벤트/조회 출처는 표로 묶습니다. 상세·공통 EventsTab·AnnotationsTab 형식은 수정하지 않습니다. 현재 조회·이전 데이터 보존·실패·권한 없음·미기록을 구분하고 VM 실행/LB 등록/애플리케이션 상태의 의미를 유지합니다. 모든 표/박스에 Mold 테마 토큰을 사용합니다.

## 검증·배포

WSL ext4 소스에서 집중 UI 회귀·lint·production UI build를 실행하고 31 GFS2/32 krbd 관리 UI 정적 파일만 배포합니다. WEB-INF/META-INF/config·서비스 PID·원 관리 JAR를 보존합니다. 실제 UI에서 라이트/다크 및 데스크톱/좁은 폭의 버튼 위치·행 대상·설정 저장·대화상자 내부/버튼 넘침·강조 박스/표 가독성을 확인하고 증거를 PR에 반영합니다. 기존 fixture와 Sparse/krbd 볼륨은 유지하며 이 작업에서 VM/디스크를 새로 만들 필요가 없습니다. 전체 Cloud 빌드/전체 CI 및 최종 장시간 테스트(#1354)는 이번 범위가 아닙니다.

## 추가 UI 표준 보완

세션 고정 구성은 vertical Form 레이블 위/입력 아래로 통일하고, Boolean 항목은 체크박스 안에 레이블을 넣습니다. 새 정책 없음은 None으로 표시하여 화면/요청 값을 일치시키며 SourceBased 기존 tablesize/expire 값도 반영합니다. 탭 이름은 VM 프로필로 축약합니다. 목록 Zone은 오토스케일 전용 셀에서만 표시하여 공통 Zone 분기와 중복되지 않습니다.

## 갱신 깜빡임 제거

VM 프로필·정책 초기 조회는 같은 자원의 재조회에서도 loading을 다시 켜던 경로를 분리합니다. LB는 규칙을 받은 직후 기존 인스턴스/세션 정책을 비우고 100ms 후 여러 개별 조회가 loading을 반복 변경하던 경로를 하나의 조회로 묶습니다. 규칙·멤버·세션·그룹 응답을 모아 한 번에 교체하고 실패한 부분은 기존 값을 유지합니다. 스케줄은 중간 빈 배열 대입을 제거합니다. 초기/다른 자원·사용자·프로젝트 조회만 기존 값을 비우고 초기 loading을 사용합니다. 같은 자원 갱신 중에는 업데이트 버튼만 진행 표시를 하며 테이블·화면 전체 스피너를 켜지 않습니다. 늦은 응답은 자원/보안 범위·조회 세대를 검사하여 무시합니다. LB 편집 완료 시 부모 로딩 토글 대신 일반 재조회를 요청합니다.

## 검증에서 추가 확인한 고정 칼럼

좁은 표에서 공통 다크 스타일의 투명한 고정 작업 칼럼 뒤로 스크롤 열이 겹쳐 보였습니다. AS 화면의 고정 칼럼에만 불투명 테마 표면/hover 배경을 적용합니다. VM 등 다른 자원 표는 변경하지 않습니다. [최종 검증](AS-09-row-actions-and-readability-validation.ko.md)을 참조합니다.
