## 집계와 변경 계약

listInstanceGroups ACL로 실제 반환되는 그룹 ID만 **한 번의 배치 SQL**로 집계한다. 같은 account의 user VM, removed 없음, Destroyed/Expunging 제외, root admin 외 display_vm=1을 사용한다. 멤버 탭은 같은 소유 범위와 groupid, state=present를 사용한다. virtualmachinecount는 virtualmachinestates 합계이며 정상 0은 0/빈 map, 조회 권한 미지원은 필드 생략/화면의 —로 구분한다. 스키마 변경은 없다.

기존 AccountManager.checkApiAccessForUser를 사용해 VM 조회 권한을 검사한다. 사용자·프로젝트 역할을 적용하고 호출 API 키도 전달한다. 별도의 ACL 검사기 목록 Bean 주입이나 추가 rate-limit 호출은 없다. 제한 API 키 검사는 단위 테스트이며 실제 클러스터의 API 키 정책 전체를 인증하지 않는다.

연결 후보·이동 그룹은 대상의 account/domain/project 범위다. 이미 현재 그룹의 VM은 후보 선택을 차단한다. 확인한 VM UUID·현재 소속·소유 범위·대상 그룹 UUID를 고정하고 요청 직전에 VM/원래 그룹/대상 그룹을 재조회한다. 소속 변경 필드는 id+groupid 또는 id+cleargroup=true이며 프로젝트 요청에는 공통 API 클라이언트가 projectid 범위를 더한다. 멤버 작업은 전원·VM/볼륨 삭제 API를 호출하지 않는다.

부분 실패는 완료/실패/불확실 결과를 구분한다. 재시도는 성공 항목을 건너뛰며 불확실 결과는 조회로 확인해야 한다. 같은 문맥 갱신은 기존 행을 유지하고 실패 시 작업을 차단한다. 권한 거부·소유/그룹/세션/탭 문맥 변경은 이전 선택·대상·초안을 제거하고 generation/scope로 늦은 응답을 거절한다. 검색 결과 수와 전체 멤버 수는 구분한다. 검색·페이지 크기·현재 페이지 정렬·탭을 URL로 복원하며 UI 전용 query는 서버에 전달하지 않는다.

## 31/32 실제 UI·API·DB

[UI 사례·요청·화면](evidence/VG-05/ui-evidence.md)과 단계별 JSON에 판정 근거를 남겼다. 테스트 전용 Stopped VM 8개(사이트별 관리자2/사용자1/프로젝트1), 동일 이름 그룹 12개, 네트워크6개, 계정2개, 프로젝트2개, 제한 역할4개를 사용했다. 마지막 표 배치 확인에는 사이트별 전용 빈 그룹 하나를 추가했고 기존 VM 후보는 읽기만 했다.

- 양쪽 관리자: 두 VM 일괄 연결 → A에서 B로 일괄 이동 → 일괄 해제. 2개 대상 UUID/소유/영향 표시, 연결 취소, 중복 연결 후보 선택 차단, VM 상세·그룹 역링크를 확인했다.
- 양쪽 일반 사용자: 자기 VM만 후보에 표시되고 동일 이름의 관리자·프로젝트 그룹이 섞이지 않았다. 연결 → 단건 이동 → 해제를 실제 수행했다. Shift+F10 메뉴와 해제 취소 뒤 원래 행 포커스 복귀도 확인했다.
- 양쪽 프로젝트 멤버: 헤더 프로젝트 보기로 전환해 해당 프로젝트 VM만 후보에 표시했다. 프로젝트 이름 열·그룹 UUID를 확인하고 연결 → 단건 이동 → 해제를 실제 수행했다.
- 31 읽기 전용 역할은 조회만 가능하고 연결/선택/작업을 차단했다. 32 VM 조회 금지 역할은 집계 필드를 생략하고 이전 행/선택을 노출하지 않았다. 실제 권한 거부 API 코드432를 확인했다. 전용 사용자 역할/활성 상태는 복구한 뒤 정리했다.
- 32 두 번째 VM의 POST에만 제어된 HTTP500을 주입했다. VM1은 B, VM2는 A로 남았고 1완료/1실패를 표시했다. 재시도 POST는 VM2 **1건**뿐이며 VM1 성공을 다시 실행하지 않았다. 이후 두 VM이 B로 이동했다.
- 32 멤버 GET의 제어된 HTTP500은 기존 1행/집계를 유지하고 변경 버튼·선택을 차단했다. 한글 오류/재시도를 표시하고 실제 재시도 후 정상 조회로 복구했다. 오류 이미지의 전환 프레임은 증거로 사용하지 않는다.
- 전체 멤버1/검색 결과0 구분, 검색 복구, 코멘트 미저장 초안의 탭 간 유지, 10개 페이지 크기·state 현재 페이지 정렬·URL reload 복원을 확인했다. UI 파라미터를 서버에 보내지 않았다.
- 31 라이트 / 32 다크, 390px 위쪽 탭/아래 컨텐츠와 표 내부 스크롤을 확인했다. 임시 viewport/XHR/캐시 설정은 복구했다.
- 그룹 삭제 확인폼은 대상 UUID·소유와 연결/코멘트 제거 및 VM·볼륨·전원·배치 보존을 표시했다. 확인 취소 후 전용 멤버 그룹을 **API로 삭제**해 영향을 대조했다. 실제 삭제된 상세는 이전 멤버/작업을 제거하고 missing 상태를 표시했다. 이 단계의 삭제 최종 제출은 UI 경로로 수행했다고 표시하지 않는다.
- 연결·이동·해제·부분 실패·그룹 삭제 각 단계에서 그룹 집계와 멤버 API/DB가 일치했다. DB는 VM당 0/1 매핑이다. 수집한 VM 속성(Stopped/host/NIC/CPU/메모리/오퍼링/템플릿/HA/동적 확장/삭제 보호 등)과 모든 수집 볼륨 응답이 전후 같았다.

## 검증 한계와 다음 작업

멤버 실제 변경은 전용 Stopped VM이다. Running VM의 새 멤버 UI 경로, 큰 멤버 수/실제 다페이지, 실시간 동시 작업·모든 API 키/역할 정책·전체 CI는 인증하지 않는다. 검색/페이지/역할·늦은 응답/삭제·owner 변경은 집중 단위 검사와 위 대표 실제 경로의 범위다. 현재 정렬은 현재 페이지에 적용한다.

실행 직전 재조회와 기존 서버의 매핑 직렬화를 사용하며 GET→POST 사이의 변경을 원자적 CAS로 보장하지 않는다. 32의 기존 전역 경보와 31의 일시적 Wall 연결 알림은 그룹 정상 조회 리본과 구분하며 이번 단계에서 전체 콘솔 무오류로 인증하지 않는다.
