# VG-06 최종 종합 회귀 설계

대상은 Epic #1357의 VG-01~05 누적 구현과 #1363의 필수 행렬입니다. 최신 Upstream `9fa65ce2a27b977e848440cb7c787411c11d585b`를 포함하는 Epic 브랜치에서 진행합니다.

## 실행 기준

- 사이트마다 전용 관리자 VM2개(Running1/Stopped1), 일반 사용자·프로젝트·제한 계정 VM 각1개, 소유별 같은 이름의 A/B 그룹과 페이지 검증용 빈 그룹을 준비합니다. 기존 자원의 소속·전원·볼륨은 변경하지 않습니다.
- API/DB 회귀 도구는 전용 prefix·UUID·소유를 검증한 뒤 계약/권한/동시 요청을 실행하고 매 단계 매핑0/1, 고아·소유 불일치·중복, VM/볼륨 불변을 확인합니다. 별도 UI 검증은 실제 브라우저 조작과 API/DB 스냅샷을 대응합니다.
- UI 핵심 경로는 무소속→A→B→해제, 관리자 타계정·일반 사용자·프로젝트·제한 역할, 이름 검증/입력 보존, 단건·일괄 삭제의 실제 제출/취소/부분 실패/재시도, 검색·정렬·페이지·탭·URL·문맥 전환입니다.
- 지연/오류 주입은 전용 브라우저 탭의 해당 XHR만 제어합니다. 실제 서버 오류나 모든 환경에서의 오류로 표시하지 않습니다. 늦은 응답, 권한 상실, 메타데이터 빈 응답과 정상0/실패 구분을 확인합니다.
- 이동/대상 삭제와 같은 VM 중복 요청을 제한된 반복 횟수로 실행합니다. 성공 후 삭제는 해제, 삭제 선행은 기존 매핑 유지/명시적 실패이며 고아·중복·타소유 매핑을 허용하지 않습니다. 원자적 GET→POST CAS나 고부하 인증으로 확대하지 않습니다.
- api/server 변경 모듈의 빌드·집중 Java 검사와 UI 모듈의 lint/회귀/운영 빌드를 구분합니다. 배포는 WEB-INF/META-INF/config 보존과 클래스/정적 해시·PID·서비스·HTTP200으로 확인합니다. 전체 Cloud 빌드·전체 CI는 실행하지 않습니다.
- VM·모든 수집 볼륨·전원·호스트 및 FTCTL 상태를 기준선과 대조한 뒤 전용 자원을 정리합니다. 이전 실패 준비 자원도 별도 추적합니다. 필수 행렬의 실패/미검증이 남으면 종합 PASS와 Epic 종료를 선언하지 않습니다.

## 준비 단계 예외

32의 최초 VLAN2001 전용 VM 기동은 `brens1f0np0-2001` 이름의 Linux 인터페이스 길이 제한으로 실패했습니다. 로그와 UUID를 보존하고 최초 Stopped VM5개/전용 네트워크4개를 정리한 뒤 사용 가능한 세 자리 VLAN으로 전용 자원을 다시 준비합니다. 이 시도는 그룹 기능 PASS 근거에 포함하지 않습니다.
