# AG-04 연결 VM 현황 및 그룹 중심 멤버 관리 검증

대상 #1417 · Epic #1413 · 누적 Draft PR #1420 · 31번 클러스터 · 2026-10-19.

## 설계와 구현

Europa `d9f068bbbba048313b6d38539651d19444c4d7c7`에 AG-01~03을 이어 구현했다. 최신 upstream Europa가 같은 커밋인지 확인했다. 작업 브랜치는 `dhslove/epic-1413-affinity-ui`이다. [설계](../../design/affinity-1413/AG-04.ko.md).

- 목록·상세에 전체 연결 VM 수, 상세→가상머신→이벤트 탭을 제공한다. `virtualmachineIds` 전체 수와 `listVirtualMachines` 조회 결과/현재 페이지를 구분한다.
- 가상머신 탭은 제목·설명→도구 모음→표→페이지 순서다. 표시 이름과 실제 내부 이름, 상태, 호스트, 계정·프로젝트·도메인 및 변경 제한 사유를 표시한다. API가 반환하지 않는 값은 정보 없음/접근 제한으로 안내한다.
- 페이지와 검색을 넘는 선택을 보존한다. 제출 직전 최신 VM·소유자·지원 상태·eligible group·전체 연결 스냅샷을 확인하고 대상 그룹만 추가/제거한다. 다른 그룹 연결을 유지한다. Running VM은 선택할 수 없고 자동 정지하지 않는다.
- VM별 접수·job·성공/실패/결과 불명을 표시한다. 실패 VM만 최신 상태를 읽어 재시도한다. 결과 불명은 재전송하지 않으며 영수증이 있으면 동일 job만 조회한다.
- 공유 VM 작업 잠금과 배치 문맥을 분리해 다른 그룹/VM 편집창의 결과를 새 목표의 성공으로 오인하지 않는다. 화면 밖 완료와 과거 배치 결과를 보존하며 VM 편집창의 최신 선택을 과거 그룹 작업으로 덮어쓰지 않는다.
- 부모 상세의 부분 갱신으로 결과창을 유지하고 Router 이력으로 VM 상세에서 돌아올 때 활성 탭·프로젝트 경로를 복원한다.
- 삭제 전 이름·소유자·전체 연결 수와 영향을 보여준다. 확인 뒤 매핑이 바뀌면 다시 확인한다. 선택 삭제도 그룹마다 순차 확인하며 성공한 대상은 다시 제출하지 않는다. 중간 취소는 남은 대상을 보존한다.

## 검증 환경과 자료 읽기

전용 일반 VM 11개, 사용자 VM 1개, 프로젝트 VM 1개, 그룹 9개, 계정·프로젝트 각 1개, L2 네트워크 2개와 제한 역할 복제본을 사용했다. VM 11번만 실제 시작해 Running 제한과 호스트 상태를 검증했다. 도메인 공유는 비어 있는 `ExplicitDedication` 그룹을 사용했으며 호스트·클러스터·Zone dedication을 추가하지 않았다.

기존 그룹 4개와 VM 119개의 ID·이름·전체 Affinity 연결 투영을 기준선으로 저장했다. 원래 FTCTL 작업 트리의 수정 파일 3개도 해시로 보존했다. 사용자 기본 역할을 수정하지 않고 전용 계정에 복제 역할만 일시 적용했다.

`evidence/ui-checks.json`의 각 항목은 실행 당시 소스를 포함한다. `64a85bf975f`와 `a2701d84c98`은 중간 배포 검증이고 `reproduced` 항목은 결함 재현이다. 파일명의 `final-` 접두사만으로 최종 소스 검증으로 간주하지 않는다. 최종 배포 검증은 `qualified-` 항목과 소스 해시를 기준으로 한다. 중간 배포의 네트워크 이벤트 일부는 버퍼에서 유실되어 전체 요청 수 근거로 사용하지 않는다. 실제 작업 영수증·API/DB 대조와 화면 증거를 함께 사용한다.

## 관련 테스트

최종 코드 `56955af91402f518a1b7911a338a77faaf8bf885`에서 집중 회귀 **14 suites / 250 tests PASS**와 변경 JS/Vue 전체 lint를 통과했다. 테스트는 집계/페이지 분리, 소유권·공유 범위, 외부 변경 감지, 다른 연결 보존, 부분 실패/unknown, 배치 결과 분리, VM 편집 선택, 부모 부분 갱신, 탭 라우팅, 삭제 영향 재확인 및 기존 생성·공유 선택기 소비자를 포함한다.

Jest의 기존 아이콘 중복 등록/jsdom 경고와 오래된 Browserslist 안내가 있다. 이 결과를 전체 Cloud CI 합격으로 해석하지 않는다. Maven/JAR/DB 스키마 변경, 전체 Cloud 빌드 또는 qemu 패키지 배포는 수행하지 않았다.

## 최종 배포·검증·정리 결과

최종 UI `56955af91402f518a1b7911a338a77faaf8bf885`를 WSL ext4에서 빌드해 정적 파일 893개를 배포했다. 패키지 SHA256 `b22891828e4e4e8ab73068e6611e061b448acc12d299a174151e46316fb7738e`, 활성 index SHA256 `fe9f627a07570dc8d77ba889e95f2c963deb966d7a28fd67700c689a606bb044`. 모든 정적 해시, WEB-INF/web.xml·META-INF 존재 상태, config symlink/해시, JAR 9개와 PID `1765167`을 확인했다. Mold active·HTTP 200이며 서비스 재시작은 없었다. 백업은 `/root/ag04-ui-deploy-refresh-20261019/webapp-backup`이다.

최종 소스의 브라우저 확인 **35건 PASS**, 중간 소스 **44건 PASS**와 **2건 결함 재현**을 분리해 기록했다. 최종 네트워크에서 연결 변경 요청 시도 8건(그중 1건은 서버 전달 전 차단한 제어 시험)과 삭제 2건을 기록했다. 기록된 UI 작업 영수증 **32개 모두 DB `job_status=1`**이다. 서버 전달 전 차단 시험에는 서버 job이 없으며 서버 작업 실패로 집계하지 않는다. 직접 API의 Running·타 소유자 거절은 별도 음성 검증이다.

최종 소스에서 첫 탭 이동 후 작업 결과창 유지와 페이지 감소 보정, 이전 unknown job 재조회/새 목표 미제출, 명시적 새 그룹 연결과 원래 영수증 불변, 외부 변경 부분 실패/실패 VM만 재시도, 실패·과거 성공 뒤 VM 편집의 최신 선택 3/4개 보존, 조회 오류·검색 0/1건·Running 차단을 재확인했다. 일반 사용자의 공유 그룹은 전체 4/가시 2, VM 조회 제한 역할은 전체 4/가시 0 및 변경 비활성, 프로젝트 그룹은 1/1과 VM→Back 탭 유지가 일치했다.

삭제는 최초 영향 11개를 확인한 뒤 외부 변경으로 10개가 되자 POST 없이 재확인을 요구했다. 재확인 후 첫 그룹만 삭제하고 두 번째 그룹을 취소해 남아 있음을 확인했다. 이후 빈 그룹을 별도 삭제했다. API/DB의 VM 13개와 다른 그룹 매핑이 유지됐고, 실행 중 VM은 호스트에서 계속 Running이었다.

전용 VM 13개·그룹 9개(UI 삭제 2개, API 정리 7개)·계정/프로젝트 각 1개·L2 네트워크 2개·복제 역할을 정리했다. API는 기준선 그룹 4개·VM 119개로 복구됐고 ID·이름·전체 Affinity 연결 투영 해시가 동일하다. DB의 전용 활성 VM·그룹·매핑·볼륨·NIC·네트워크·계정(내부 프로젝트 계정 포함)·사용자·프로젝트·역할 카운터 **10종 모두 0**이다. 제거 시각을 가진 VM 감사 행은 DB에 남으며 활성 자원으로 세지 않는다. 실제 실행했던 `i-2-661-VM`은 호스트 도메인·루트 디스크·config-drive 파일 부재까지 확인했다. 기존 FTCTL 수정 파일 3개의 해시도 동일하다.

정리 중 이미 UI에서 삭제한 그룹의 ID 조회가 API 431을 반환해 정리 스크립트가 멈췄다. 전체 자원 인벤토리에서 존재하는 전용 ID만 처리하도록 보완하고 재개했다. VM 삭제 13건의 성공 영수증은 복구·대조했으며 이후 그룹/종속 자원 정리와 기준선 비교가 통과했다. API/DB에 대한 직접 변경이나 기존 운영 자원 수동 정리는 하지 않았다.

## 남는 경계와 다음 이슈

`updateVMAffinityGroup`은 전체 연결 교체 API이고 expected-version/CAS가 없다. UI가 확인 뒤 외부 변경을 탐지하지만 **최종 조회와 서버 쓰기 사이의 동시 변경을 원자적으로 차단하지 못한다**. 서버의 원자적 delta/CAS 및 모든 호출자 잠금 계약 확장은 별도 API 과제이다. 앱 전체 새로고침을 넘는 작업 영수증 영속화도 제공하지 않는다. job ID 없는 결과 불명은 Cloud 작업/소유자 목록 확인을 안내한다.

다음은 **#1418 AG-05**다. VM 메뉴의 목록·상세·탭·탭 콘텐츠·대화상자를 같은 조건에서 비교해 버튼 순서/간격, 빈 값/긴 값, 소유자 이름·UUID, 상태 문구/접근성, 번역 칩, 라이트/다크와 좁은 화면을 정돈한다. 이번 기능 계약과 결과 보존을 회귀 기준으로 유지한다. 그다음 **#1419 AG-06**에서 전체 역할/테마/화면 행렬과 실제 호스트 배치를 검증한다. Epic과 PR은 후속 작업을 위해 Open/Draft로 유지하며 이번 요청에는 병합이 포함되지 않는다.
